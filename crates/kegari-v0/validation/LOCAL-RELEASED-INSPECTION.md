The current implementation separates immutable historical release completion
from current delivery readiness. One-attempt successful releases can receive the
same complete seal as terminal supersede chains, with no ancestor holds to remove.
A versioned signed binding preserves the configured provider identities; legacy
seals retain their prior queue semantics but cannot invent missing dependency
bindings. Runtime consumption revalidates exact references, current configuration,
complete actual provider observations, prerequisite visibility and repository
access. The dependent's authenticated generation pin still selects the outcome.

Typed historical inspection keeps workspace UUID, full native parent identity,
recorded work and diagnostics outside the current scheduling projection. Read-only
Overview/Show/Open resolution may use those identities; current mutation
resolution remains separate. Missing or unsafe URLs are unavailable. Display data
does not create a completion capability or dependency credit.

Root owns shared integration, serial Cargo and this record. Git agent owns
completion production and its actual local Git/provider-wire fixtures. Codex
agent owns presentation/resolution and facade tests. Config agent owns graph
regressions and independently reviews cache semantics. No live agents, remote
mutations, deployment, installation or denied native probes are part of this work.

The graph regression uses existing opaque no-release domain evidence with
explicitly synthetic upstream checks. It tests exact historical pins and native
missing prerequisites, not the actual release-completion cache. Real completion
fixtures must separately establish that path. Historical no-release-required
runtime credit still needs its own durable production integration: its current
delivery snapshot is invalidated by a new prerequisite generation.

The new temporary command runner refuses label reuse and captures before/after
source inventories plus actual Rust/Cargo version identities for each invocation.
