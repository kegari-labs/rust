# Exact remote Git objects

`remote_objects` reads a provider-observed exact commit into a new private, immutable object substrate. It never fetches into the configured operator checkout. The admitted worker or delivery scope, current provider repository identity, exact source reference or PR identity, and original pinned Git executable are checked before use. Authorized fork PRs retain their full admitted identity; they are not converted into same-repository PRs.

The native transport currently supports the verified `api.github.com` / `github.com` route. It uses HTTPS smart Git protocol v2 with the host's scoped credential, without placing a secret in a child environment, command argument, URL, or retained record. It requests a complete, non-thin pack for exact object IDs. Redirects, shallow/filter/URI packs, unsupported object formats and unsolicited protocol sections fail closed. Other provider origins require an explicit verified native mapping and currently return `unsupported_git_origin`.

Before Git receives bytes, the parser verifies framing, the pack checksum, object counts, zlib expansion, delta source/result bounds, aggregate reconstructed bytes and bounded delta depth/work. Native Git then performs `index-pack --strict`, full strict connectivity validation, exact commit/tree validation and exact reachable-object inventory comparison. Missing ancestry and extra unrelated objects fail. Imports run through the current operation's gated, cancellable Git runner and durable process journal. A private signed record and an acknowledged effect receipt are both required before returning `VerifiedObjectSource`.

Default limits are 64 MiB of pack data, 1 MiB of protocol overhead, 100,000 objects, 16 MiB per object, 128 MiB for each aggregate inflated/reconstructed representation, and delta depth 64. These are representation bounds, not a total process-memory claim: decoded entries and reconstructed objects can coexist, approaching twice the expansion bound plus wire/pack buffers and metadata. Filesystem verification separately caps retained entries and total bytes. The HTTP implementation enforces the requested streaming response limit.

An interrupted or rejected import is preserved in its original private quarantine. Existing receipts never authorize a fresh transfer or blind retry. Cache reuse verifies the signed source record, acknowledged receipt, original binary bytes, object inventory, complete bounded filesystem digest and current provider source. A changed ref, changed PR identity, force fence, changed source bytes or lost final authority cannot produce a usable source. Explicit reconciliation of an uncertain import is still required before any separate recovery action.

The first implementation requires a real admitted worker/preparation or release permit. A STOPPED cache miss cannot acquire objects through the read-only metadata authority. Worker preparation, staging observation and native parent candidate assembly consume the acquisition path. Existing sources can be discovered read-only while STOPPED only after current repository/account/configuration, signed source, actual acknowledged receipt, pinned binary and retained filesystem checks. Delta recovery chooses a source containing every exact original and replacement root and then revalidates its complete Git object closure. Cross-operation acquisition deduplication, explicit uncertain-import recovery and enterprise origin mappings remain separate work. Repository instructions and context must be discovered from the actual selected clone commit; the operator checkout remains attribution/configuration provenance, not a substitute for newly acquired `AGENTS.md` content.

## Evidence

Run the deterministic protocol and actual disposable Git fixtures with:

```sh
RUSTUP_TOOLCHAIN=stable CARGO_HOME=/private/tmp/kegari-v0-cargo-cache \
  cargo test -p kegari-v0 --lib remote_objects --offline
```

The deterministic regressions cover actual local upload-pack/index-pack interchange, exact tree/ancestry, binary data, executable mode, symlinks, dirty operator-checkout preservation, cache tampering, missing ancestry, source/force races, loss of final authority, authorized fork identity, malformed/truncated/checksum failures, aggregate reconstructed expansion and delta depth. Missing or changed actual receipts, changed pinned binaries, STOPPED cache misses and exact retained-root selection have explicit negative fixtures. An acquired-clone fixture verifies fetched instructions while preserving configured operator attribution, and the fork fixture imports the exact base as well as head. The two-root squash fixture reproduces the exact reviewed delta after importing both the squash and original head. HTTP responses and logical authority are injected fixtures; Git subprocesses and object validation are real. No live remote access, live agent evaluation or native sandbox qualification is established by these tests.

Protocol references: [Git protocol v2](https://git-scm.com/docs/protocol-v2), [smart HTTP](https://git-scm.com/docs/http-protocol), [pack format](https://git-scm.com/docs/gitformat-pack), [index-pack](https://git-scm.com/docs/git-index-pack), and [GitHub token authentication](https://docs.github.com/en/enterprise-cloud%40latest/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).
